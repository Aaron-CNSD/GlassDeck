Mac 上如何安装
和使用 MC 启动器？

适用 GCL v0.2.0 · 更新于 2026 年 10 月 26 日

GCL 是面向 macOS 13+ 的开源 Minecraft Java版启动器开发预览。本指南从下载格式开始，帮助你先准备原版环境，再逐步尝试模组、整合包与联机。

本页内容
  1. 选择 DMG、ZIP 还是 JAR
  2. 首次启动与 Java
  3. 模组和整合包
  4. 本地皮肤与联机
  5. 常见问题和验证范围

1. 先选择正确的下载格式

请从 GCL 官方 GitHub Release 下载，或返回 GCL 官网下载区。

  • DMG：推荐的 Mac 安装方式。打开镜像，把 GCL.app 拖入 Applications（应用程序）。
  • ZIP：解压获得同一个 GCL.app，打开即可。
  • JAR：这是 Mac 原生程序的 Java 启动入口，本身需要 Java 8+。它不提供 Windows 或 Linux 版本，也不能在 iPhone 上启动游戏。

目前支持 macOS 13+，安装包包含 Apple Silicon 与 Intel 二进制。应用临时签名、未经 Apple 公证，请保留系统安全保护并按系统提示处理。不要因为安装教程而关闭 Gatekeeper。

2. 准备用户名、Java 和原版游戏

  1. 打开 GCL，在「开始游戏」中输入 3–16 位英文字母、数字或下划线组成的本地用户名。
  2. 选择 Minecraft 版本和内存。当前范围为 1.19+；第一次建议先验证原版环境。
  3. 点击「下载并启动」。GCL 按版本准备对应的 Java、游戏文件、依赖和资源，首次下载需要保持联网。
  4. 长时间没有进展时，可取消后重试；出错时查看软件中的日志入口。

ZIP / DMG 原生应用无需你预先安装 Java；JAR 入口需要 Java，是两件不同的事。本地用户名不能进入要求 Microsoft 正版验证的服务器。

3. 安装加载器、模组与整合包

先在「新建 / 原版」配置中选择游戏版本，再选择 Forge、NeoForge、Fabric 或 Quilt 和对应加载器版本，点击安装。不同加载器与游戏版本不能任意混用；Forge / NeoForge 完整安装仍有未验证情况。

在「资源下载」中搜索 Modrinth 模组、整合包或光影，并选择匹配的资源版本。普通模组的额外依赖需要另行安装，光影需要兼容的 Iris / OptiFine 等支持。

已有 .mrpack 文件时，使用「导入整合包」入口，等待文件下载和校验完成，再选择新建的整合包配置。CurseForge ZIP 当前不支持。不同整合包保留独立目录，导入失败不会登记不完整的启动配置。

4. 使用本地皮肤与陶瓦房间

在「我的皮肤」中选择小于 2 MB 的 64×64 或 64×32 PNG，GCL 准备兼容的 CustomSkinLoader 配置，并把图片保存在本机。原版配置会创建 Fabric 配置；其他玩家不会自动看到你的本地皮肤。

陶瓦联机首次需要在 macOS 系统安装器中完成组件授权，并允许本地网络访问。房主进入存档并「对局域网开放」后创建房间，再把房间码发给朋友。双方必须匹配游戏、加载器和模组，跨网连接取决于公共节点与 NAT 条件。

5. 遇到问题时先看这些

  • JAR 打不开：确认是 Mac，并已准备 Java 8+；没有 Java 时优先使用 DMG 或 ZIP。
  • 模组不生效：核对游戏版本、加载器和额外依赖，确认文件安装到当前启动配置。
  • 整合包无法导入：确认是受支持的 .mrpack，而不是 CurseForge ZIP。
  • 房间连不上：确认系统组件、本地网络权限、房主局域网开放状态及双方配置一致。
  • 游戏退出：在日志中查看具体错误，再到 GitHub Issues 提供版本、系统、CPU 架构与脱敏日志。不要公开凭据或房间码。
这是开发预览：编译、下载、配置与本地协议已有检查，但完整进入世界、游戏内皮肤和真实双机跨网联机尚未验证。页面内容不代表所有游戏版本或整合包都已经实机通过。

v0.2.0：管理实例与排查问题

在“版本管理”中新建、重命名独立实例，并导出配置备份 ZIP；在“模组管理”中搜索、启用或停用本地模组。每个配置可以保存独立的内存和窗口设置。“任务与日志”可查看日志、复制诊断摘要与导出文件。备份 ZIP 暂不支持自动还原，也不是 mrpack。
